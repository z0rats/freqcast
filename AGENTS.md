# AGENTS.md

Android app (Kotlin, Jetpack Compose) for playing internet radio streams (HTTP/HTTPS, incl. HLS `.m3u8`) via ExoPlayer/Media3, with local station storage in Room and background playback.

**Topic-specific detail lives in `docs/architecture/`, not here** — this file is re-read in full on every request, so it stays to what's relevant on *most* changes. Read the matching file before working in its area:

- `docs/architecture/discovery.md` — Discover screen, `StationUrlResolver`, `WebViewStreamSniffer`, Radio Browser API. Check first for any "can't find/add station from URL" report.
- `docs/architecture/alarms-and-shortcuts.md` — App Shortcuts, wake-up alarms.
- `docs/architecture/backup.md` — export/import/share.
- `docs/architecture/ui-layout.md` — station icons, theming/dimens, landscape/two-pane, accessibility.
- `docs/architecture/testing-ci.md` — Roborazzi/screenshot tests, CI workflow specifics.

## Project layout

- Single module: `app/`. Dependency versions live in `gradle/libs.versions.toml`; reference as `libs.foo.bar` / `alias(libs.plugins.foo)`, never hardcode a `group:artifact:version` string. Compose artifacts without a `version.ref` (`androidx-compose-ui`, `-material3`, etc.) are constrained by the `androidx.compose:compose-bom` platform instead — bump Compose via `composeBom`, not per-artifact.
- `docs/index.html`: self-contained static landing page (GitHub Pages source, once enabled in repo settings — not yet confirmed live), hand-styled to match the in-app palette (`ui/theme/Color.kt`) and copy from `README.md`/`fastlane/.../full_description.txt`. Uses real screenshots from `docs/screenshots/` (mirrors `fastlane/metadata/android/en-US/images/phoneScreenshots/`) and `docs/demo.gif` — when a user-facing feature or screen changes, update this page's copy/screenshots alongside README, not just AGENTS.md. `docs/ru/index.html` is a full Russian translation mirroring the same structure/CSS (assets referenced via `../`); both pages carry a `.lang-switch` pill in the nav (always visible, not hidden by the mobile nav-links collapse) linking to each other — keep both in sync on any copy change, and add corresponding `.lang-switch` links/translated copy if more locales are added. `docs/architecture/*.md` is unrelated internal dev documentation (see below), not part of the public site — it just happens to share the `docs/` root.
- `app/src/main/java/com/freqcast/`: `data/` (Room + repository), `ui/` (Compose screens + `ui/components`, `ui/playback`, `ui/theme`), `util/`.
- Lint: ktlint (`ktlintCheck` / `ktlintFormat`); `.editorconfig` allows PascalCase names on `@Composable` functions. CI: `.github/workflows/ci.yml` (test + Roborazzi verify, lint, `assembleDebug` on every push/PR), `release.yml` (tag `v*` → signed `assembleRelease` → GitHub Release).
- `./gradlew` locally (wrapper is committed, matches CI's Gradle version). `Makefile` wraps common invocations (`format`, `lint`, `test`, `build`, `check`, `install`/`run`) — keep in sync if a task name changes.
- Baseline Profile: `app/src/main/baselineProfiles/*.txt` (AGP 9.x reads this *directory*, not the old single `src/main/baseline-prof.txt` — that path silently produces an empty profile). Hand-curated: two wildcard rules covering `com.freqcast.**`; verify with `./gradlew :app:expandReleaseArtProfileWildcards` and grep for `com/freqcast`. No instrumented benchmark module (project has no `androidTest`), so re-curate by hand if the package structure changes shape.
- Release builds: `minifyEnabled true` + `shrinkResources true` (R8; `app/proguard-rules.pro` is the stock empty template, nothing project-specific needed). Signed via `signingConfigs.release`, reading `RELEASE_KEYSTORE_PATH`/`RELEASE_KEYSTORE_PASSWORD`/`RELEASE_KEY_ALIAS`/`RELEASE_KEY_PASSWORD` from env — if `RELEASE_KEYSTORE_PATH` is unset, signing is skipped and Gradle produces an unsigned APK (no debug-signing fallback). `release.yml` decodes `RELEASE_KEYSTORE_BASE64` to a workspace-local file, deleted with `if: always()`. `keystore/release.keystore` is gitignored, never committed — keep it and its password in a password manager; losing it means future releases can't use the same signing key. `dependenciesInfo { includeInApk = false; includeInBundle = false }` is set because AGP's Play dependency-metadata signing block gets rejected by F-Droid's build scanner.
- F-Droid distribution (`gitlab.com/fdroid/fdroiddata`, `metadata/com.freqcast.yml`): `AutoUpdateMode: Version` + `UpdateCheckMode: Tags` means F-Droid's bot auto-detects new `v*` tags and opens its own metadata MR — no action needed there. But it does **not** write changelog text. Every version bump must include a matching `fastlane/metadata/android/en-US/changelogs/<versionCode>.txt` (≤500 chars, no file = no "what's new" shown for that release, silently) committed in the same release. Reproducible builds are wired up (`Binaries:` + `AllowedAPKSigningKeys:` in the metadata yml, verified via `apksigcopier compare --unsigned` between a clean-clone `assembleRelease` and the published GitHub Release APK) — this pins F-Droid's trust to the current signing key from `keystore/release.keystore`; switching keys later breaks it for existing users.

## Architecture conventions

- Minimize dependencies: prefer implementing something ourselves over pulling in a library for it. See `LocationProvider` (plain `LocationManager`, not `FusedLocationProviderClient`), `RadioBrowserApi` (own `OkHttpClient`+`org.json`, not Retrofit/DI), `DragDropState` (hand-rolled drag gesture, no reorder library). Only reach for a dependency when the in-house cost/risk clearly outweighs a small hand-rolled implementation.
- `data/RadioStationRepository` is the only class touching `RadioStationDao`/`AppDatabase` directly — `ViewModel`s take a `RadioStationRepository`, never an `AppDatabase`/`Context`. Created via `RadioStationRepository.create(context)`.
- Two `ViewModel` styles: `MainViewModel`-style (plain `StateFlow`s + fire-and-forget `fun`s, optionally a `Channel`-backed `events` flow for one-shot feedback) for simple CRUD/search screens; `AddStationViewModel`-style (`UiState` data class + `Channel`-backed events) for screens with form validation. Pick based on screen complexity.
- **Full-row `@Update` trap**: `AddStationViewModel.save()` rebuilds a whole `RadioStation` from form fields, and `repository.updateStation()` is a full-row `@Update` — any field missing from the rebuilt object silently resets to its data-class default on edit. Every new `RadioStation` field must be added to `AddStationUiState` and threaded through *both* `save()` branches (new + edit), not just the entity. Bit us once with `isFavorite` (now removed); `sortOrder` and `genre` follow the correct pattern today.
- Deleting a station is immediate but undoable, not confirmation-gated: `MainViewModel.deleteStation()` deletes + reloads + emits `MainScreenEvent.StationDeleted`; `MainScreen` shows a Snackbar with Undo. `undoDelete()` re-inserts the same `RadioStation` (same `id`), which SQLite accepts as an explicit rowid, restoring original position (`getAllStations()` orders by `id ASC` within same-`sortOrder` rows).
- Playback (`RadioPlaybackService`, `PlaybackController`, retry/reconnect), Android Auto, and the home screen widget: see `docs/architecture/playback.md`.
- Station icons, theming/dimens, landscape/two-pane layout, accessibility, `StationListActions`: see `docs/architecture/ui-layout.md`.
- App Shortcuts and wake-up alarms: see `docs/architecture/alarms-and-shortcuts.md`.

## Localization

- `res/values/strings.xml` is the source of truth (English); `res/values-<lang>/strings.xml` (ru, es, zh-rCN) must mirror the exact same `name` keys — Android silently falls back to the default string for a missing key rather than erroring. Format-argument placeholders (`%1$s`, `%1$d:%2$02d`, ...) must match verbatim in position/type (args are passed positionally). `app_name` stays untranslated everywhere.

## Database & migrations

- `RadioStation` has unique indices on `name`/`streamUrl` (schema v3) on top of app-level `isNameTaken`/`isUrlTaken` checks. `AppDatabase` has `exportSchema = true` (JSONs in `app/schemas/`) — **schema changes must ship a real `Migration` + schema snapshot**, never `fallbackToDestructiveMigrationFrom` (only allowed for pre-2.0 installs jumping from v1, no v1 snapshot exists). `MIGRATION_2_3` is the dedupe-then-constrain template: delete pre-existing `name`/`streamUrl` collisions (keep oldest row) before creating the unique indices.
- `AppDatabaseMigrationTest` verifies migrations against hand-built `LegacyVN...` entity/DAO/DB snapshots (not the real `RadioStation`/`AppDatabase`, which already carry later columns) — needs `kspTest 'androidx.room:room-compiler:2.8.4'`. Templates: `MIGRATION_3_4` (plain `ALTER TABLE ADD COLUMN`), `MIGRATION_2_3` (dedupe-then-constrain), `MIGRATION_7_8` (full create/copy/drop/rename rebuild, needed to *drop* a column since `DROP COLUMN` support depends on the bundled SQLite version). `MIGRATION_8_9` (new `wake_alarms` table) reuses the real `RadioStation`/`RadioStationDao` in its `LegacyV8Database` since `radio_stations`' shape is unchanged at v8.
- **List ordering**: `RadioStation.sortOrder` (`Int` ascending, schema v8) plus drag-to-reorder replaced the old favorites/pinning (`isFavorite DESC, id ASC`) — a free manual order and auto-pin-to-top can't coexist. `RadioStationDao.getAllStations()` orders `sortOrder ASC, id ASC` (the single source of truth — list, export, Android Auto browse tree, widget skip buttons all use it).
  - `insertStation()` auto-assigns `sortOrder = getMaxSortOrder() + 1` (appends), overwriting the passed-in value. `restoreStation()` (used by `undoDelete()`) is the one exception — inserts as-is, preserving `id`/`sortOrder`.
  - `MainViewModel.moveStation()` mutates the in-memory list only (per-frame drag feedback, no DB write); `persistStationOrder()` commits via `updateSortOrder(orderedIds)` (`@Transaction`) once the drag ends.
  - Drag gesture: `ui/components/DragDropState.kt` (hand-rolled `detectDragGesturesAfterLongPress`, since this Compose BOM has no built-in `LazyColumn` reorder support). Attached to the whole `LazyColumn`; long-press-then-still naturally disambiguates from `StationItem`'s per-item `detectHorizontalDragGestures` swipe-to-reveal (immediate directional drag). Disabled entirely while `searchQuery` is non-blank (reordering a filtered subset is ambiguous).
    - **`onDrag` only accumulates raw finger movement (`draggedDistance += offset.y`) — the swap-target search and auto-scroll live in `settle()`, called at most once per rendered frame** (`rememberDragDropState`'s `while (true) { withFrameNanos {}; state.settle() }`), never directly from `onDrag`. `onDrag` fires once per raw pointer-move sample, measurably faster on-device than layout/recomposition keeps up — confirmed via screen recording: several `onDrag` calls landing before a frame's `state.layoutInfo` had caught up with the *previous* call's `onMove` each independently found (and applied) a swap target against that same stale snapshot, cascading into multiple wrong-pair swaps per frame. Visibly: a station several positions away from the dragged one would jump on its own, two cards would briefly both show the dragging-highlight, or the highlighted "dragging" card would become a completely different station than the one under the finger. Rate-limiting to one `settle()` per frame — the same cadence layout actually updates at — closes this.
    - `draggingItemLayoutInfo` looks the dragged item up by its stable `LazyListItemInfo.key` (the station's id), not by `draggingItemIndex` — an index-based lookup resolves to *whichever other item currently occupies that slot* in a stale (pre-recomposition) snapshot, not the item actually being dragged. Key-based lookup always finds the same real composable regardless of whether layout has caught up with `onMove`'s reorder yet, which is why `draggingItemInitialOffset` is captured once at `onDragStart` and never touched again.
    - `MainScreen`'s per-item `isDragging` flag (drives the elevated `Card`/`translationY` offset) is likewise keyed off `station.id == dragDropState.draggingItemKey`, not `index == dragDropState.draggingItemIndex` — `draggingItemIndex` is a plain Compose state written synchronously inside `settle()`, but `stations` (`itemsIndexed`'s `index` source) arrives through `MainViewModel.filteredStations`, a `combine()`'d `Flow` collected via `collectAsState()`; that extra hop can land a frame behind `draggingItemIndex`'s own update, briefly comparing the new index against the *old* list order and highlighting the wrong station right after a swap. `draggingItemKey` sidesteps this the same way `draggingItemLayoutInfo`'s key-based lookup does — no second, independently-updating list to go stale against.
    - `settle()`'s swap-target search compares the dragged card's **leading edge** against a neighbor's matching edge (`startOffset < item.offset` moving up into `currentIndex - 1`, `endOffset > item.offset + item.size` moving down into `currentIndex + 1`), not a shared-midpoint-inside-the-neighbor's-full-rect check. A midpoint check is symmetric and has no memory of which way it last swapped: holding the finger still exactly on a swap boundary lets a couple of pixels of ordinary touch jitter toggle "is the midpoint inside this item's rect" back and forth, re-triggering `onMove` in alternating directions every frame — confirmed via screen recording showing the top two items visibly flip-flopping order every 2-3 frames while dragging into the very first slot (a first attempt blaming `MainViewModel.filteredStations`'s `combine()`-Flow lag for this instead — gating the search on `draggingItemLayoutInfo`'s index having caught up with `draggingItemIndex` — measurably changed nothing, ruling that theory out). Requiring a full edge crossing means reversing needs an equally large move back, the same hysteresis [aclassen/ComposeReorderable's `ReorderableState.chooseDropItem()`](https://github.com/aclassen/ComposeReorderable) (the reference this gesture was adapted from) gets from comparing edges instead of a shared center point.
    - `settle()` calls `state.scrollBy(overscroll)` directly (a suspend call, safe since `settle()` itself only ever runs inside `rememberDragDropState`'s per-frame `LaunchedEffect`) rather than posting through a channel to a separate collector — once swap-search and auto-scroll are both already gated to one-per-frame, there's nothing left for a channel to buffer.
  - `isDragging` (computed in `MainScreen`) drives the dragged item's elevated `Card`/border and `graphicsLayer { translationY }`/`zIndex(1f)` — no separate drag-handle icon, the whole card is the drag target (long-press-then-move).
- `RadioStation.genre` (schema v5, nullable `TEXT`): Discover-added stations get it from the directory's `tags` field; manual adds get an optional free-text field. Matched by `MainViewModel.filteredStations`'s search; shown in `StationItem`'s subtitle in place of the raw URL when present.
- `RadioStation.isHls` (schema v6, `Boolean` default `false`): sourced from the directory's `hls` flag on Discover add; manual adds always get `false`. Makes `RadioPlaybackService.isHlsUrl()` more reliable than its `"m3u8" in url` heuristic — see `docs/architecture/discovery.md`.
- `RadioStation.radioBrowserUuid` (schema v7, nullable `TEXT`): the directory's `stationuuid`, same "Discover sets it, manual gets null" pattern — lets `RadioPlaybackService` register a "click" with the directory on play.
- `radio_tags` table (schema v11, `MIGRATION_10_11`) caches the directory's `/json/tags` catalog for Discover's GENRE-tab autocomplete — see `docs/architecture/discovery.md` for the sync/threshold invariants.
- `RadioStation.isCurated` (schema v12, `MIGRATION_11_12`): marks a row from the hardcoded `CuratedStations.pack`, seeded once into a fresh install's list by `MainViewModel.seedCuratedStationsIfNeeded()` (guarded by `SettingsStore.hasSeededCuratedPack` so it never re-runs after a user deletes some or all of it — deletion is the only way to remove them day-to-day, there's no ongoing Settings toggle). `SettingsViewModel.restoreCuratedStations(context)` is the one-shot undo for that: re-inserts any pack entry missing by name/streamUrl (same skip-on-duplicate check as station import), behind the "Restore curated stations" row in Settings. Deliberately *not* threaded through `AddStationUiState`: editing a curated station's full row resets this to `false` like any field left out of the rebuild — here that's the intended "no longer as curated" behavior, not the full-row-`@Update` trap above. Drives the "Curated" pill in `StationItem`'s `StationCard`. Each pack entry's real site icon is bundled under `app/src/main/res/raw/curated_*` (downloaded once at dev time, not fetched over the network at seed time) — `CuratedStations.withResolvedIcon(context, station)` copies the bundled bytes through `IconStorage` into a normal local icon file before insert, so a curated station's icon needs no special-casing anywhere else in the app (rendering, export, widget, Android Auto all just see an ordinary image path). The first curated station also gets a one-time swipe-to-reveal peek-and-highlight animation (`StationItem`'s `playSwipeHint`, `SettingsStore.hasShownSwipeHint`) teaching the edit/share/delete gesture: a long initial delay (~1.8s) before it fires since it'd otherwise play underneath the first-launch notification-permission system dialog, then a full-threshold reveal (not just a peek) with the Delete button itself pulsing (scale + glass_accent ring) — Delete is deliberately the target since it's rightmost in the reveal row and the one action a user actually needs to discover here.

## Testing

- **Never launch or drive an emulator/physical device yourself** (`adb`, `input tap`, `screencap`, booting an AVD) to verify a change. Connected devices may be the user's real phone with personal apps — blind taps can background the app and land in something unrelated. Verify with `./gradlew test`/`ktlintCheck`/compile, and describe what to visually check for the user to confirm themselves.
- Unit tests only (`app/src/test`, no `androidTest`); CI's `test` job runs `./gradlew test`. Room DB tests and anything needing a `Context` use Robolectric (`@Config(sdk = [29])`).
- Coverage: Kover (`app/build.gradle`'s `kover {}` block), reporting only the `debug` variant — `./gradlew koverXmlReportDebug`/`koverHtmlReportDebug` (default output paths, not overridden except `xmlFile`). CI's `test` job uploads the XML to Codecov (`codecov/codecov-action@v5`, needs a `CODECOV_TOKEN` repo secret) with `fail_ci_if_error: false`, so a Codecov outage never reds out the pipeline — coverage is informational, not a merge gate (no `koverVerify`/minimum-bound rule configured).
- `StreamRecorder`/`TimeshiftController`/`StreamValidator`/`RadioBrowserApi` tests use a local `MockWebServer` (all four construct their own `OkHttpClient`, not injected). Any test touching `org.json` needs `RobolectricTestRunner` even without a `Context` — the plain Android stub jar throws `RuntimeException: not mocked` on real `org.json` calls. Same trap with media3 model classes: constructing a bare `PlaybackException` or `MediaItem`/`ProgressiveMediaSource` (not just using one from a `Context`-backed component) throws the identical `not mocked` `RuntimeException` without Robolectric — this is why `TimeshiftController` stays a `DataSource.Factory`-returning seam rather than building `MediaItem`/`MediaSource` itself: doing so would force `TimeshiftControllerTest` onto Robolectric too.
- `RadioPlaybackService`'s pure decision logic (`isHlsUrl`, `loadBrowsableStations`, `playFromBrowseTree`) is `internal` so tests can call it without the full `MediaLibraryService`/ExoPlayer lifecycle — though `RadioPlaybackServiceAutoTest` does construct the full service via `Robolectric.buildService(...).create().get()` (real `ExoPlayer`+`MediaLibrarySession` come up fine under Robolectric; it's specifically the `MediaBrowser` Binder round-trip that's avoided). Retry backoff/classification (`retryDelayMs`, `isRetryableNetworkError`) live on `playback/ConnectionRetryPolicy` instead, and are covered by `ConnectionRetryPolicyTest` directly — no service/Robolectric needed.
- ViewModel tests exercising a suspend fn that hops onto real `Dispatchers.IO` (`StreamValidator`/`RadioBrowserApi` calls) must poll for expected state (`awaitTrue { condition }` wrapped in `withTimeout`) rather than a single `advanceUntilIdle()`, which only fast-forwards the test dispatcher's own queue.
- Even fully-virtual tests (`StandardTestDispatcher` + in-memory Room) need a *content*-based poll condition, not count-based, when asserting after a `viewModelScope.launch` update that doesn't change collection size (e.g. a `sortOrder` reorder) — a count-only condition can already be true before the coroutine runs, returning without ever driving the scheduler. Poll the actual field expected to change.
- `IconStorageTest` opts into `@GraphicsMode(GraphicsMode.Mode.NATIVE)` (like screenshot tests) since plain Robolectric fakes `BitmapFactory` decode results — needed to assert real downsampled pixel dimensions.
- **Never call a suspend function inside `awaitTrue`'s poll lambda** (or any tight `while (!cond) { advanceUntilIdle() }` loop) — the poll itself would suspend on a real background thread, and nothing drives the virtual scheduler forward while you're suspended: a real deadlock, only broken by `withTimeout`. When there's no synchronous side effect to poll, poll a plain `StateFlow` field twice in sequence (transient "in progress" value, then it flipping back) rather than reading the DB from inside the poll.
- `advanceUntilIdle()`-busy-looping stops being reliable once a background chain does more than one real-dispatcher hop back-to-back (network IO → `withContext(IO)` → sequential Room calls) — repeated calls with no elapsed wall-clock time can race ahead of a still-in-flight later hop. `delay()`-based retries don't fix this either (`delay`/`withTimeout` under `runTest` use virtual time, never truly sleep). Fix: a plain `while` loop bounded by real `System.currentTimeMillis()`, reading state via `runBlocking { ... }` (a genuinely separate blocking call, safe here since it doesn't participate in the virtual scheduler) with a real `Thread.sleep(20)` between attempts.
- `util/WebViewStreamSniffer.kt`'s core orchestration has **zero automated coverage** (Robolectric's `ShadowWebView` is a non-functional stub), same class of gap as the `MediaBrowser` Binder round-trip note above — see `docs/architecture/discovery.md` for exactly what's pulled out as pure and unit tested there instead.
- `androidx.core.content.FileProvider` caches its resolved roots per authority **for the whole test JVM**, not just per test class — confirmed in practice: a second test class calling `FileProvider.getUriForFile(..., "com.freqcast.fileprovider", ...)` against its own (differently-pathed) Robolectric activity intermittently fails with `IllegalArgumentException: Failed to find configured root`, depending on which test class Gradle happens to run first in the same forked worker. `StationShareTest` already claims this authority as the suite's one FileProvider-touching test (hence its own "single test method" doc) — don't add a second one anywhere else; test the rest of a FileProvider-adjacent function (e.g. `ClipExport.export`) via its early-return branches only, see `ClipExportTest`.
- A test that calls `RadioPlaybackService.onStartCommand` directly (see `RadioPlaybackServiceStartCommandTest`) without first seeding/reading the shared `AppDatabase.getDatabase()` singleton can fail on pure timing, not logic: the *first* test in a given JVM to touch it pays for the full migration chain synchronously, which can outlast a short `awaitStationName`-style poll if this happens to be that first test (reproduces reliably when run standalone via `--tests`, since a full-suite run usually has an earlier test warm the singleton first). Fix: an unconditional `@Before` that does `runBlocking { AppDatabase.getDatabase(context).radioStationDao().getAllStations() }` — over `runBlocking` (no timeout), not inside the test's own timed poll.
- Kover/JaCoCo-style line coverage can misattribute a line inside a lambda passed to a suspend/callback API (a bare `continuation.resume(...)` or a suspend call immediately followed by `return@`) as "missed" even when a passing test demonstrably executes it — confirmed independently for both `AlarmEditViewModel.save()`'s `updateAlarm` branch and `LocationProvider.requestSingleUpdate`'s no-provider branch, each backed by a test that exercises exactly that line. Don't chase an isolated single-line gap inside an otherwise well-tested function on the coverage report's word alone — check for an existing test first; the report is a more reliable signal for whole untested files/functions than for single lines inside covered ones.
- Screenshot tests and CI workflow specifics (Roborazzi, Kover CI hang, the `record-screenshots.yml` fix-forward loop): see `docs/architecture/testing-ci.md`.
