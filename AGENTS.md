# AGENTS.md

Android app (Kotlin, Jetpack Compose) for playing internet radio streams (HTTP/HTTPS, incl. HLS `.m3u8`) via ExoPlayer/Media3, with local station storage in Room and background playback.

**Topic-specific detail lives in `docs/architecture/`, not here** — this file is re-read in full on every request, so it stays to what's relevant on *most* changes. Read the matching file before working in its area:

- `docs/architecture/playback.md` — `RadioPlaybackService`, `PlaybackController`, retry/reconnect, Android Auto, home screen widget, AppFunctions.
- `docs/architecture/discovery.md` — Discover screen, `StationUrlResolver`, `WebViewStreamSniffer`, Radio Browser API. Check first for any "can't find/add station from URL" report.
- `docs/architecture/alarms-and-shortcuts.md` — App Shortcuts, wake-up alarms.
- `docs/architecture/backup.md` — export/import/share.
- `docs/architecture/ui-layout.md` — drag-to-reorder, station icons, theming/dimens, landscape/two-pane, accessibility, `StationListActions`.
- `docs/architecture/testing-ci.md` — Roborazzi/screenshot tests, CI workflow specifics.

**Why things are the way they are lives in `docs/adr/`** (one file per decision, `NNNN-slug.md`; index + rules in `docs/adr/README.md`). Area pages and this file state *what is* and cite `ADR-NNNN`; the ADR holds the reason, the accepted cost and the rejected alternatives. Before changing something an ADR covers, read it — a "Rejected" line is usually the bug you're about to reintroduce. When a change makes a new decision (a competent person could have chosen otherwise, and it changes the code), add an ADR in the same commit; when it reverses one, mark the old one `Superseded by ADR-NNNN` (never delete or renumber) and check the ADRs that cite it.

## Project layout

- Single module: `app/`. Dependency versions live in `gradle/libs.versions.toml`; reference as `libs.foo.bar` / `alias(libs.plugins.foo)`, never hardcode a `group:artifact:version` string. Compose artifacts without a `version.ref` (`androidx-compose-ui`, `-material3`, etc.) are constrained by the `androidx.compose:compose-bom` platform instead — bump Compose via `composeBom`, not per-artifact.
- `docs/index.html`: static landing page (GitHub Pages source, once enabled in repo settings — not yet confirmed live), styled by the shared `docs/site.css` (chamfered corners, hard offset shadows, wide black uppercase Archivo display type with Unbounded as the Cyrillic fallback, JetBrains Mono eyebrows; palette from `ui/theme/Color.kt`; `html[lang=ru]` rules there shrink the display sizes) and copy from `README.md`/`fastlane/.../full_description.txt`. Uses real screenshots from `docs/screenshots/` (mirrors `fastlane/metadata/android/en-US/images/phoneScreenshots/`) and `docs/demo.gif` — when a user-facing feature or screen changes, update this page's copy/screenshots alongside README, not just AGENTS.md. `docs/ru/index.html` is a full Russian translation mirroring the same structure/CSS (assets referenced via `../`); both pages carry a `.lang-switch` pill in the nav (always visible, not hidden by the mobile nav-links collapse) linking to each other — keep both in sync on any copy change, and add corresponding `.lang-switch` links/translated copy if more locales are added. `docs/demo/player.{js,css}` is an interactive browser replica of `MainScreen` + `DiscoverStationsScreen` (live Radio Browser calls straight from the browser, CORS is open) + `SettingsScreen` (UI only), mounted at `#fc-demo` in both pages' hero (the first screen; sized by viewport height; one shared script, strings keyed by `data-lang`, copied from `strings.xml`), playing the real `CuratedStations.pack` streams via `<audio>` (volume slider sits in the page-level strip above the phone, outside the device frame, default ~30% amplitude, hidden where `audio.volume` is read-only, i.e. iOS); icons in `docs/demo/*.png` are downscaled copies of `res/raw/curated_*` — when the pack, `StationItem`/`NowPlayingBottomBar` visuals, or `Color.kt` change, update it too (no automated coverage; check in a browser). `docs/architecture/*.md` and `docs/adr/*.md` are internal dev documentation, not part of the public site — they just share the `docs/` root.
- `app/src/main/java/com/freqcast/`: `data/` (Room + repository), `ui/` (Compose screens + `ui/components`, `ui/playback`, `ui/theme`), `util/`.
- Lint: ktlint (`ktlintCheck` / `ktlintFormat`); `.editorconfig` allows PascalCase names on `@Composable` functions. CI: `.github/workflows/ci.yml` (test + Roborazzi verify, lint, `assembleDebug` on every push/PR), `release.yml` (tag `v*` → signed `assembleRelease` → GitHub Release).
- `./gradlew` locally (wrapper is committed, matches CI's Gradle version). `Makefile` wraps common invocations (`format`, `lint`, `test`, `build`, `check`, `install`/`run`) — keep in sync if a task name changes.
- Baseline Profile: `app/src/main/baselineProfiles/*.txt` (AGP 9.x reads this *directory* — the old single `src/main/baseline-prof.txt` path silently produces an empty profile). Hand-curated: two wildcard rules covering `com.freqcast.**`; verify with `./gradlew :app:expandReleaseArtProfileWildcards` and grep for `com/freqcast`. No `androidTest`, so no benchmark module — re-curate by hand if the package structure changes shape.
- Release builds: `minifyEnabled true` + `shrinkResources true` (R8; `app/proguard-rules.pro` is the stock empty template). Signed via `signingConfigs.release`, reading `RELEASE_KEYSTORE_PATH`/`RELEASE_KEYSTORE_PASSWORD`/`RELEASE_KEY_ALIAS`/`RELEASE_KEY_PASSWORD` from env — if `RELEASE_KEYSTORE_PATH` is unset, Gradle produces an unsigned APK (no debug-signing fallback). `release.yml` decodes `RELEASE_KEYSTORE_BASE64` to a workspace-local file, deleted with `if: always()`. `keystore/release.keystore` is gitignored, never committed. `dependenciesInfo { includeInApk = false; includeInBundle = false }` because F-Droid's build scanner rejects AGP's Play dependency-metadata signing block.
- Update check skipped for store installs by a runtime installer check, not a flavor — ADR-0014. Add new store installer ids to `InstallSource.STORE_INSTALLERS`.
- F-Droid (`gitlab.com/fdroid/fdroiddata`, `metadata/com.freqcast.yml`): reproducible builds pinned to the current signing key, bot auto-detects `v*` tags — ADR-0015. **Every version bump must include `fastlane/metadata/android/en-US/changelogs/<versionCode>.txt`** (≤500 chars) in the same release, or that release silently shows no "what's new".

## Architecture conventions

- Minimize dependencies, no DI framework — ADR-0001.
- `data/RadioStationRepository` is the only class touching `RadioStationDao`/`AppDatabase`; ViewModels take a repository, never an `AppDatabase`/`Context` — ADR-0002. Created via `RadioStationRepository.create(context)`. Export/import is in `data/StationBackupIO.kt`, not the repository.
- **Adding a station without per-field validation goes through `RadioStationRepository.insertStationIfAbsent(station, onNameCollision)`** — ADR-0003. Don't add a call site with its own inline `isNameTaken`/`isUrlTaken`; `AddStationViewModel.finalizeSave()` is the one deliberate exception.
- Two ViewModel styles: `MainViewModel`-style (plain `StateFlow`s + fire-and-forget `fun`s, optionally a `Channel`-backed `events` flow) for simple CRUD/search screens; `AddStationViewModel`-style (`UiState` data class + `Channel`-backed events) for screens with form validation.
- **Edit path**: `RadioStation.withFormEdits()` copies form fields onto the loaded station; never rebuild a `RadioStation(...)` from scratch there — ADR-0004.
- Delete is immediate + Snackbar Undo (`undoDelete()` → `restoreStation()`, same `id`/`sortOrder`) — ADR-0005.
- Main-screen search falls back to an inline Radio Browser search when empty — ADR-0030.
- Playback, Android Auto, widget: `docs/architecture/playback.md`. Icons, theming, layout, drag-to-reorder, accessibility: `docs/architecture/ui-layout.md`. Shortcuts and alarms: `docs/architecture/alarms-and-shortcuts.md`.

## Localization

- `res/values/strings.xml` is the source of truth (English); `res/values-<lang>/strings.xml` (ru, es, zh-rCN) must mirror the exact same `name` keys — Android silently falls back to the default string for a missing key rather than erroring. Format-argument placeholders (`%1$s`, `%1$d:%2$02d`, ...) must match verbatim in position/type (args are passed positionally). `app_name` stays untranslated everywhere.

## Database & migrations

- `RadioStation` has unique indices on `name`/`streamUrl` (schema v3) on top of app-level `isNameTaken`/`isUrlTaken` checks.
- **Schema changes ship a real `Migration` + schema snapshot** (`app/schemas/`), never a destructive fallback — ADR-0006 (templates: `MIGRATION_3_4` add column, `MIGRATION_2_3` dedupe-then-constrain, `MIGRATION_7_8` full rebuild to drop a column).
- `AppDatabaseMigrationTest` verifies migrations against hand-built `LegacyVN...` entity/DAO/DB snapshots — the real `RadioStation`/`AppDatabase` already carry later columns (`LegacyV8Database` reuses the real ones since `radio_stations` didn't change at v8). Needs `kspTest 'androidx.room:room-compiler:2.8.4'`.
- **List ordering**: `sortOrder ASC, id ASC` from `RadioStationDao.getAllStations()` is the single source of truth (list, export, Auto browse tree, widget/notification skip) — ADR-0007. `insertStation()` appends; `restoreStation()` preserves. Drag-to-reorder: `docs/architecture/ui-layout.md`.
- Directory-sourced columns — Discover sets them, manual add gets defaults: `description` (v5, ex-`genre`; directory `tags` or optional free text; matched by search, shown in `StationItem`'s subtitle instead of the URL; old backups' `"genre"` key still read), `isHls` (v6; directory `hls` flag, more reliable than `RadioPlaybackService.isHlsUrl()`'s `"m3u8" in url` heuristic), `radioBrowserUuid` (v7; `stationuuid`, for the play click — ADR-0023).
- `radio_tags` table (v11, `MIGRATION_10_11`) caches `/json/tags` for GENRE autocomplete — ADR-0043.
- `isCurated` (v12, `MIGRATION_11_12`) + the curated pack seeded once, bundled `res/raw/curated_*` icons, "Restore curated stations" — ADR-0012. Curated stations are read-only (no Edit in the swipe row) — ADR-0054. One-time swipe hint — ADR-0013.

## Testing

- **Never launch or drive an emulator/physical device yourself** (`adb`, `input tap`, `screencap`, booting an AVD) to verify a change. Connected devices may be the user's real phone with personal apps — blind taps can background the app and land in something unrelated. Verify with `./gradlew test`/`ktlintCheck`/compile, and describe what to visually check for the user to confirm themselves.
- Unit tests only (`app/src/test`, no `androidTest`); CI's `test` job runs `./gradlew test`. Room DB tests and anything needing a `Context` use Robolectric (`@Config(sdk = [29])`).
- Coverage: Kover, `debug` variant only — `./gradlew koverXmlReportDebug`/`koverHtmlReportDebug`. Informational, never a gate — ADR-0016.
- `StreamRecorder`/`TimeshiftController`/`StreamValidator`/`RadioBrowserApi` tests use a local `MockWebServer` (all four construct their own `OkHttpClient`). Any test touching `org.json` needs `RobolectricTestRunner` even without a `Context` — the plain Android stub jar throws `RuntimeException: not mocked`. Same with constructing bare media3 model classes (`PlaybackException`, `MediaItem`, `ProgressiveMediaSource`) — see ADR-0017 for why `TimeshiftController` stays a `DataSource.Factory` seam.
- `RadioPlaybackService`'s pure decision logic (`isHlsUrl`, `loadBrowsableStations`, `playFromBrowseTree`) is `internal` for tests; `RadioPlaybackServiceAutoTest` constructs the full service via `Robolectric.buildService(...).create().get()` (only the `MediaBrowser` Binder round-trip is avoided). Per-stream state is on the pure `playback/PlaybackSession`, covered by `PlaybackSessionTest` (ADR-0022).
- ViewModel tests exercising a suspend fn that hops onto real `Dispatchers.IO` (`StreamValidator`/`RadioBrowserApi` calls) must poll for expected state (`awaitTrue { condition }` wrapped in `withTimeout`) rather than a single `advanceUntilIdle()`, which only fast-forwards the test dispatcher's own queue.
- Even fully-virtual tests (`StandardTestDispatcher` + in-memory Room) need a *content*-based poll condition, not count-based, when asserting after a `viewModelScope.launch` update that doesn't change collection size (e.g. a `sortOrder` reorder) — a count-only condition can already be true before the coroutine runs. Poll the actual field expected to change.
- `IconStorageTest` opts into `@GraphicsMode(GraphicsMode.Mode.NATIVE)` (like screenshot tests) since plain Robolectric fakes `BitmapFactory` decode results — needed to assert real downsampled pixel dimensions.
- **Never call a suspend function inside `awaitTrue`'s poll lambda** (or any tight `while (!cond) { advanceUntilIdle() }` loop) — the poll suspends on a real background thread while nothing drives the virtual scheduler: a real deadlock, only broken by `withTimeout`. With no synchronous side effect to poll, poll a plain `StateFlow` field twice in sequence (transient "in progress" value, then it flipping back).
- `advanceUntilIdle()`-busy-looping stops being reliable once a background chain does more than one real-dispatcher hop back-to-back (network IO → `withContext(IO)` → sequential Room calls). `delay()`-based retries don't fix it (virtual time under `runTest`). Fix: a plain `while` loop bounded by real `System.currentTimeMillis()`, reading state via `runBlocking { ... }`, with a real `Thread.sleep(20)` between attempts.
- `util/WebViewStreamSniffer.kt`'s orchestration has **zero automated coverage** (Robolectric's `ShadowWebView` is a stub) — see `docs/architecture/discovery.md` for the pure tested parts and the manual checklist.
- `androidx.core.content.FileProvider` caches resolved roots per authority **for the whole test JVM** — a second test class calling `FileProvider.getUriForFile(..., "com.freqcast.fileprovider", ...)` intermittently fails with `IllegalArgumentException: Failed to find configured root`, depending on class order. `StationShareTest` is the suite's one FileProvider test (single test method) — don't add a second; test the rest of a FileProvider-adjacent function (e.g. `ClipExport.export`) via its early-return branches only, see `ClipExportTest`.
- A test calling `RadioPlaybackService.onStartCommand` directly (see `RadioPlaybackServiceStartCommandTest`) can fail on timing if it's the first in the JVM to touch `AppDatabase.getDatabase()` — that test pays for the full migration chain synchronously (reproduces reliably standalone via `--tests`). Fix: an unconditional `@Before` doing `runBlocking { AppDatabase.getDatabase(context).radioStationDao().getAllStations() }` — outside the test's own timed poll.
- Kover line coverage can mark a line inside a lambda passed to a suspend/callback API (a bare `continuation.resume(...)`, or a suspend call followed by `return@`) as missed even when a passing test executes it (confirmed for `AlarmEditViewModel.save()`'s `updateAlarm` branch and `LocationProvider.requestSingleUpdate`'s no-provider branch). Check for an existing test before chasing an isolated single-line gap; the report is reliable for whole untested files/functions, not single lines.
