# Backup: export / share / import

Station export/import and per-station sharing. Split out of `AGENTS.md` because it's only relevant when touching `SettingsScreen`'s import/export or `util/StationShare.kt`.

- Backup JSON shape (`{name, streamUrl, customIcon, genre, isHls, radioBrowserUuid}[]`, `data/StationBackupJson.kt`) deliberately excludes `sortOrder` (not meaningful across devices — imports append via normal `insertStation()`) and `isFavorite` (older backups with that key just get it ignored on import). Used both by `exportStationsToJson()` (all stations) and per-station sharing (single in-memory `RadioStation`). `importStationsFromJson()` reads the same shape, wired to `SettingsScreen`'s Import (SAF `OpenDocument`, MIME filter `*/*` — none of the four importable formats have a reliable SAF MIME type via `content://` URIs).
- `RadioStationRepository.importStations()` is `SettingsScreen`'s single import entry point: sniffs the picked file's content (not extension/MIME) and dispatches to `importStationsFromJson()` for a JSON array (`content.trimStart().startsWith("[")`), else `importStationsFromPlaylist()`. The latter delegates format detection to `data/PlaylistImport.kt`, which tries — in order — XML containing an `<outline>` tag (OPML, via `android.util.Xml`'s pull parser, so `PlaylistImportTest` needs `RobolectricTestRunner` even with no `Context`, same reason as `org.json`), `#EXTM3U`-prefixed text (M3U/M3U8, `#EXTINF:duration,Title` line names the URL line that follows; a bare URL line uses itself as the name), or `[playlist]`-prefixed `key=value` text (PLS, `FileN`/`TitleN` pairs keyed by their numeric suffix, order-independent). Throws `IllegalArgumentException` if none match. Only `name`/`streamUrl` exist in any of these three formats, so every other `RadioStation` field stays at its entity default — same skip-on-duplicate/failed-on-missing-field semantics as JSON import.
- "Export stations" and per-station "Share" (swipe action) both go through `util/StationShare.kt` (`Intent.ACTION_SEND` file attachment, so it reaches Telegram/WhatsApp/email directly). Needs a `FileProvider` (`res/xml/file_paths.xml`, authority `com.freqcast.fileprovider` hardcoded in `StationShare` — keep in sync with `applicationId`). `testOptions.unitTests.includeAndroidResources = true` is required for Robolectric to see it. `FileProvider` statically caches resolved roots per authority for the process lifetime, so `StationShareTest` uses a single test method rather than one per `@Test`.
- Track title (ICY metadata via `StreamRecorder`, shown in `PlaybackScreen`) has a copy-to-clipboard button (`LocalClipboardManager`). Long single-line values that need to stay fully readable (station name/track title) route through `ui/components/MarqueeText.kt` (plain values: `NowPlayingBottomBar`'s `MiniPlayerCardFull`, `DiscoverStationsScreen`'s result rows) or `PlaybackScreen`'s private `CopyableLabel(marquee = true)` (values that also need copy-on-long-press: `TrackTitleRow`) — both wrap `Modifier.basicMarquee(iterations = Int.MAX_VALUE)` internally; don't inline that modifier at a new call site, extend one of these two instead. Must pass `iterations` explicitly; the no-arg default is `MarqueeDefaults.Iterations = 3` (ported from `TextView`'s classic marquee), so an unqualified `Modifier.basicMarquee()` scrolls exactly 3 times then freezes permanently, which reads as "the marquee stopped working" rather than a one-off animation completing. The notification's own title/text has **no marquee equivalent** — Android disables `RemoteViews` text animation for 3rd-party apps — but Android 11+'s system media-controls panel (drawn by SystemUI from `MediaSession` metadata, not the `Notification` object) does auto-scroll, which is why `updateMediaItemMetadataForTrack()` keeps `MediaMetadata.setArtist(trackTitle)` current on every ICY change.
